# Prompt used to let an AI write the import Cypher

The import Cypher was generated by an AI assistant (Claude) from the normalised schema, reviewed, and saved in `src/cypher/import_*.cypher`. It runs inside the ingestion workflows (the `Build ... batches` Code nodes wrap it with the data). Two fixes were needed after testing against Neo4j 2026 (Cypher 25): `CALL () { ... }` scope syntax, and a plain `SET` for the embedding property. The prompt below reproduces the request.

---

Write Neo4j Cypher (Neo4j 5) to import Magic cards into this schema:

(Card {oracle_id}) -[:PRINTED_IN]-> (Set {code})
(Card) -[:HAS_COLOR]-> (Color {code}),  (Card) -[:HAS_COLOR_IDENTITY]-> (Color)
(Card) -[:HAS_SUPERTYPE]-> (Supertype {name}),  (Card) -[:IS_TYPE]-> (CardType {name}),  (Card) -[:HAS_SUBTYPE]-> (Subtype {name})
(Card) -[:HAS_KEYWORD]-> (Keyword {name}),  (Card) -[:LEGAL_IN]-> (Format {name})
(Rule {number}) -[:SUBRULE_OF]-> (Rule {number})   // 702.19 -> 702
(Keyword) -[:DEFINED_BY]-> (Rule)

Requirements:
- The input is a parameter `$rows`, a list of flat maps (one per card) with list fields for colors, types, subtypes, keywords, legal_formats.
- Must be idempotent: running it twice creates no duplicates (MERGE on the unique key, SET for the rest).
- One statement, using UNWIND and FOREACH for list fields.
- Also write the constraints for every unique key.
- Also write a statement that links Keyword to the Rule whose title equals the keyword name, limited to sections 701 and 702.
